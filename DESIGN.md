# Active design direction

The user rejected the initial dashboard-style concept. The active reference is `/workspace/generated_images/exec-b14fb567-ae90-4da4-bc42-fc98d1964ef2.png`.

The user subsequently requested a first-person operating room. The preparation reference is `/workspace/generated_images/exec-6fb1fdae-3462-4f30-a3d3-a22810c24813.png`. Preparation uses walk/look/interact, instrument pickup, a physical monitor, and a transition to the stable surgical view. The operating-room geometry is original runtime 3D art, not the concept photograph used as a backdrop.

Full-bleed operative scene; small native game HUD; no website header, serif headline, card dashboard, or sidebar. The surgical field carries the visual attention. Top-left compact SUTURE wordmark and case name, objective beneath; top-right audio, time, pause. Bottom-left controls; bottom-center three instrument slots; bottom-right compact monitoring; small field-relative depth ruler. Separate in-game overlays for case selection, help, pause, and results.

Tokens: near black #071010, warm white #edece5, muted white #b6bfba, sage #b9cfb4, warning #d8b98c, blood/injury #b55c55. Sans-serif system/Arial UI, monospace numerical data. Uppercase labels 10–11px, UI 13px, objective 24px, small border radius 2–4px, thin lines. No decorative glows. Motion communicates tool contact, fluid change, and state.

Allowed game copy: SUTURE; Instrument lab; Find your depth; Keep the tip in view; Suction; Irrigation; Bipolar; Move; Scroll; Shift; Hold LMB to operate; Pause; Case files; Field guide. Additional mission, pause, controls, feedback, settings, and result copy is functionally required and will remain concise.

Intentional production adaptation: use an actual atlas-derived 3D cortical mesh, authored Blender instruments, and interactive 3D fluid/contact effects rather than the static photoreal anatomical image in the concept. This is essential for real depth, manipulation, and honest collision feedback. Generated imagery supplies a drape material and instrument-thumbnail artwork; UI text and controls remain native. The simulation is a simplified prototype, with explicit omissions in the case brief.

Verification will compare the native 1672×941 reference composition with a browser capture, inspect other desktop sizes and small-screen handling, and document actual differences without claiming photorealism or clinical validation.
